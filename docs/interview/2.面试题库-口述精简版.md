# 一、Go（30 题）

**Q1 defer** — LIFO。`return` 拆三步：赋值返回值 → 跑 defer → 返回，所以**命名返回值能被 defer 改**。坑：循环里别 defer。

**Q2 slice** — 三元组 `{指针,len,cap}`，赋值只拷贝头、**底层数组共享**。小于 256 翻倍，大于 256 约 1.25 倍。坑：`s2 := s1[:2]` 再 append 会覆盖 s1。

**Q3 map 并发** — **不安全，直接 fatal 且 recover 抓不住**。RWMutex（通用）/ sync.Map（读多写少、key 稳定）/ 分片锁（高并发）。CI 跑 `-race`。

**Q4 make / new** — make 只造 slice/map/chan 返回**可用对象**；new 返回**零值指针**，业务基本不用。

**Q5 零值** — nil slice 能 append、nil map 能读不能写、nil chan 永久阻塞。所以 Go 不需要构造函数。

**Q6 传参** — **只有值传递**。slice 传头结构副本、map 传指针，所以改元素可见；要改变量本身传 `*T`。

**Q7 string/[]byte** — 互转**必然拷贝**。热路径用 unsafe 免拷贝，拼串用 `strings.Builder`。

**Q8 interface** — 非空 iface = `itab+data`，空 eface = `_type+data`。**typed nil != nil**，函数返回 error 要显式 `return nil`。

**Q9 goroutine** — 初始栈 **2KB** 可增长、用户态调度、切换几十纳秒。能开百万个，代价是**泄漏要靠 ctx 管**。

**Q10 GMP** — **G 协程、M 线程、P 调度资源**（M 必须持有 P 才能执行 G）。本地队列 256，取活顺序：**本地 → 全局 → netpoll → 偷别的 P**。系统调用 P 被 sysmon 抢走；1.14 起超 10ms 发 SIGURG **异步抢占**。

**Q11 channel 边界** — nil：收发永久阻塞、close panic。closed：**发送 panic、接收拿零值 + ok=false**、重复 close panic。

**Q12 优雅关闭** — **谁发送谁关闭**，接收方永不 close。多发送者 `wg.Wait()` 后统一 close。生命周期用 ctx 管、channel 只传数据。

**Q13 select** — 多路就绪**随机选**，`default` 变非阻塞，nil case 永久禁用。循环里别用 `time.After`（换 NewTimer + Stop）。

**Q14 context** — **树形，Done 关闭即广播**。首参传、不塞结构体；WithValue 只放 traceID；创建后必须 `defer cancel()`。

**Q15 三件套** — WaitGroup 计数等待；Once 全局只执行一次（双检）；Pool **临时对象复用、每次 GC 清空**，**不是连接池**。

**Q16 GC** — **三色标记 + 并发清扫**，混合写屏障让 STW 亚毫秒。`GOGC=100` 表示堆翻倍才回收，容器里配 `GOMEMLIMIT`。

**Q17 逃逸** — 返回指针、闭包捕获、装箱、大小编译期不定 → 上堆。验证 `-gcflags="-m"`。

**Q18 锁** — Mutex **等超 1ms 进饥饿模式**直接交锁。RWMutex **写优先**，写多反而更慢。都不可重入、不可复制。

**Q19 atomic vs mutex** — atomic 管**单个字**，mutex 管**多字段不变量**，`atomic.Value` 整块换配置。

**Q20 泛型** — 用在**容器和算法库**，业务少用；能接口解决就别上；不支持泛型方法。

**Q21 error** — `%w` 包装、`errors.Is/As` 判定、底层给哨兵错误；并发用 errgroup 聚合。

**Q22 panic/recover** — panic 只给**程序错误**；recover 必须在 defer 里**直接调**；**每个 goroutine 都要自带 recover**。

**Q23 worker pool** — 可退出（`select + ctx.Done()`）、单任务 recover、`close` 后 `Wait` 排空、**提交侧背压**（带超时阻塞或溢出队列，不静默丢）。

**Q24 缓存击穿** — 分片锁降竞争 + **singleflight 合并回源** + 过期抖动防雪崩 + 空值缓存防穿透。

**Q25 竞态检测** — `-race` 基于 **happens-before + 向量时钟**，只能查**实际走到**的路径，开销 5~20 倍，放 CI。

**Q26 死锁检测** — 所有 P 空闲、无 timer、无 netpoll 事件才抛 fatal。**局部死锁查不出来**，靠 pprof goroutine 看堆积。

**Q27 热重启** — `SIGUSR2` → fork+exec 传 **listener fd**（清 CLOEXEC）→ 子进程 `net.FileListener` accept → 父进程 `Shutdown` **排空在途** → 退出。别忘 worker / MQ 消费者 / 指标 flush / 日志重开 / **注册中心反注册**。

**Q28 配置热加载** — plugin 限制多（仅 Linux、cgo、版本必须一致、不能卸载）→ 用 `fsnotify` + `atomic.Pointer` 换指针；**解析失败保留旧配置**。

**Q29 pprof** — CPU 采 30 秒、heap 看 `inuse_space`、goroutine 查泄漏、block/mutex 查竞争。**火焰图看最宽的叶子**。

**Q30 PHP vs Go** — PHP-FPM **一请求一进程 + 阻塞 IO**，卡在 max_children；Go **协程 + epoll**，2KB 栈。IO 密集 Go 有量级优势，CRUD 还要看生态与交付。

# 二、Node.js（25 题）

**Q1 是什么** — V8 + libuv + 系统 API。浏览器有 DOM、Node 有 fs/net/Buffer；强在 **IO 密集 + 前后端同构**。

**Q2 事件循环** — 六阶段 **timers → pending → idle → poll → check → close**。阶段之间先清 nextTick 再清 Promise 微任务。IO 回调里 `setImmediate` 早于 `setTimeout(0)`。

**Q3 单线程吗** — **JS 单线程，进程不是**。主线程 + **libuv 线程池（默认 4）** 处理 fs/DNS/zlib/crypto；**网络 IO 走 epoll 不走线程池**。

**Q4 同步/异步** — 同步异步看"等不等结果"，阻塞非阻塞看"线程是否被占"。伪异步杀手：大 JSON.parse、bcrypt 同步版、ReDoS。

**Q5 CJS/ESM** — CJS 同步、运行时、**值拷贝**、有 cache；ESM **静态分析**（tree-shaking）、异步、**活绑定**、要写扩展名。

**Q6 Buffer** — **堆外内存**，不受 V8 堆限制。`alloc` 清零安全，`allocUnsafe` 快但可能读到旧数据；小 Buffer 来自 8KB 池。

**Q7 Stream** — 四种 Readable/Writable/Duplex/Transform。**背压**：`write()` 返回 false 就等 `drain`。`pipe` 不管错误，生产用 `pipeline`。

**Q8 Express** — app 是**函数数组**，`next()` 是游标；`next(err)` 直奔错误处理；**错误中间件必须 4 个参数**；`res.send` 后要 return。

**Q9 Koa** — **洋葱模型**，`await next()` 前后都能写，进出对称。核心是 `koa-compose` 递归 `dispatch(i)`。

**Q10 依赖** — dependencies 运行时、devDependencies 构建期、peerDependencies 插件声明宿主。`^` 放 minor、`~` 只放 patch；**lock 文件必须提交**。

**Q11 cluster** — master 监听端口 fork worker，**分发 server handle**，默认 **round-robin**。**进程不共享状态**，session/限流要外置 Redis。

**Q12 child_process** — exec 走 shell 且缓冲输出（注入风险）、execFile 不走 shell、spawn **流式**、fork 带 **IPC**。

**Q13 CPU 密集** — `worker_threads` 同进程独立 V8 + SharedArrayBuffer + transferList 零拷贝；child_process 隔离好但开销大。

**Q14 内存泄漏** — 全局缓存无上限、闭包持有 req/res、定时器没清、Map 只增不删、监听器泄漏、原生模块。**对比两次堆快照看 Retained Size**。

**Q15 异常** — `uncaughtException` 说明进程状态未知，**记日志后 exit(1)**，交给 pm2/K8s。async 路由用 `asyncHandler` 包一层。

**Q16 监听器警告** — 默认 maxListeners=10，超了通常意味着**循环里注册监听器** → 用完 `off`，一次性事件用 `events.once`。

**Q17 大文件** — 上传：**流式落临时文件 + 分片 + 秒传（hash）+ 合并 + 转对象存储**；下载：`createReadStream` + **Range 206** 断点续传。恒定内存。

**Q18 MySQL 连接池** — 连接是**有状态长连接**，**事务必须同一连接**。坑：忘记 `release()` 会让请求全 hang。

**Q19 JWT** — 存 httpOnly Cookie（防 XSS，防 CSRF）或 Header。payload 只是 Base64 **不是加密**。**Refresh 一次性轮换**，登出靠黑名单/版本号。

**Q20 V8 优化** — Ignition 解释 → 热点 JIT。**隐藏类 + 内联缓存**：别动态增删属性、构造时初始化所有字段、保持单态、数组别混类型。

**Q21 长连接网关** — 四层转发支持 upgrade；**`userId → gatewayId` 存 Redis**；跨节点用 Pub/Sub 定向下发；**心跳 30s + 半开清理**；看 `bufferedAmount` 做背压。

**Q22 爬虫** — `p-limit` 控并发 + 令牌桶 + BullMQ 调度（重试/去重/优先级）+ 代理 UA 池 + **批量 upsert** + 三段监控。

**Q23 BFF** — 聚合、裁剪、协议转换、鉴权灰度。风险：多一跳故障点，必须有超时降级，**别把业务写进去**。amis = **配置化 BFF**。

**Q24 NestJS** — 装饰器 + `reflect-metadata` 存类型 → 容器**递归解析构造函数**（默认单例）。分层 Controller→Service→Repository，模块 imports/exports 显式依赖。

**Q25 CPU 100%** — `clinic flame` / `--cpu-prof` / `top -Hp`。根因按概率：**大 JSON 序列化、ReDoS、死循环、大数组排序、同步写日志、GC 压力**。先摘流量止血。

# 三、AI（24 题）

**Q1 Transformer** — `softmax(QKᵀ/√d_k)V`；**除 √d_k 防点积方差过大导致 softmax 饱和**。多头关注不同关系。并行 + 长依赖，代价 O(n²)。

**Q2 Token** — 子词切分，中文约 1~2 字/token。贵的原因：**注意力 O(n²) + KV Cache 占显存 + 按 token 计费**。

**Q3 三阶段** — 预训练给**知识**、SFT 给**指令格式**、RLHF 给**偏好对齐**（DPO 省掉奖励模型）。

**Q4 采样** — Temperature 控随机性（**0 用于代码/抽取**），Top-k 砍长尾，Top-p 按累积概率。别同时大改 k 和 p。

**Q5 Prompt** — Few-shot 给示例、**CoT 先推理**、**结构化靠 JSON Schema/FC**。五段式：角色+任务+约束+示例+格式；**prompt 要版本化**。

**Q6 幻觉** — 概率续写不是查证。缓解：**RAG 接地 + 强制引用 + 约束解码 + 工具查实时 + 低置信转人工**。

**Q7 Embedding** — **余弦看方向不看长度**，归一化后等于点积。铁律：**索引与查询必须同一模型**。

**Q8 RAG** — 切分→向量化→入库→召回→**重排**→拼 prompt→生成。四坑：按结构切 300~800 token 带重叠、**混合检索（向量+BM25）**、**rerank 性价比最高**、要求"只依据材料、给引用、不知道就说不知道"。

**Q9 向量库** — pgvector（**同库同事务、可 SQL 过滤，千万级首选**）、Milvus（十亿级但运维重）、Qdrant（轻量过滤强）、ES（自带 BM25）。

**Q10 Function Calling** — **模型不执行函数**，只按 schema 输出 JSON；应用校验→执行→回灌→循环。tool 描述就是 prompt。

**Q11 Agent** — LLM + 工具 + 记忆 + 规划。ReAct：**Thought → Action → Observation**。护栏：最大步数、单步超时、工具白名单、危险操作人工确认。

**Q12 MCP** — **JSON-RPC** 标准化 Tools/Resources/Prompts。**FC 是模型怎么调工具，MCP 是工具怎么接入**，把 M×N 变 M+N，类比 LSP。

**Q13 流式** — **SSE**：`text/event-stream` 单向、走 HTTP、自带重连。关缓冲（`X-Accel-Buffering: no`）、心跳、**客户端断开要 abort 上游省 token**。

**Q14 上下文** — 短期滑动窗口+摘要；长期**向量记忆 + 结构化记忆**。顺序：去重裁剪 → 检索召回 → 再摘要。**噪声会拉低准确率**。

**Q15 选型** — 知识型/要更新/要引用 → **RAG**；改风格格式 → **微调**；少量文档一次分析 → **长上下文**。口诀：**先 RAG，再 prompt，最后微调**。

**Q16 评估** — 建 **golden set**（100~500 条含无答案与对抗样本）。检索看 Recall@k/MRR，生成看 **Faithfulness**，端到端用人工 + **LLM-as-judge**（要抽样校验）。

**Q17 注入** — 直接注入 + **间接注入（RAG 检索到恶意文档）**。防护分层：**权限隔离最硬 + 输入分隔 + 参数白名单 + 危险操作确认 + 审计**。

**Q18 运维问答机器人** — ① 数据（文档+工单+SOP，按标题切、打产品线标签）② 检索（pgvector+BM25 + metadata 权限 + rerank）③ 生成（只依据材料、给引用）④ 安全（租户隔离、脱敏、**写操作只给链接**）⑤ 工程（SSE、语义缓存、限流、评测回归）。**先做只读闭环**。

**Q19 AI 代码质量** — 六道门：给足上下文、小步生成、**gofmt/vet/lint + 单测 + SAST**、先让 AI 写测试、CR 重点看（吞异常/资源泄漏/SQL 参数化/日志脱敏）、用缺陷率度量。**把 AI 产出当初级同事的 PR 审**。

**Q20 LLM 网关** — 统一协议、多模型路由、限流配额、**按 token 计费**、超时降级、**精确+语义缓存**、trace（TTFT/错误率）、内容安全。难点：**流式计费**与背压。

**Q21 推理优化** — **KV Cache** 换时间（长上下文显存大头）；量化 FP16→INT8/4；**PagedAttention 分页管 KV，消碎片、吞吐数倍**。

**Q22 日志分析** — 结构化 + 脱敏 → **规则/统计粗筛** → 只对失败和慢任务跑 LLM（<5%）→ 输出 `{阶段,根因,建议}`。价值看 **MTTR 下降**。

**Q23 记忆** — 三层：上下文（工作记忆）、Redis（会话/任务状态）、向量库+结构化库（长期）。写入判断"是否含新事实"防污染，读取要**权限校验**。

**Q24 编排** — LangGraph 是**状态图**（State+Node+条件边+checkpoint 断点续跑+人工介入）；Dify/Coze 可视化但可控弱。**能用确定性 workflow 就别上自主 Agent**。

# 四、PHP（20 题）

**Q1 生命周期** — `MINIT → RINIT → 执行 → RSHUTDOWN → MSHUTDOWN`。**请求结束内存全释放**，所以不怕泄漏、也不适合常驻。

**Q2 opcache/JIT** — 缓存 opcode 省编译；JIT 只对 CPU 密集有效；生产 `validate_timestamps=0` + 发布时 reload。

**Q3 == 与 ===** — `==` 做类型转换（`"1e3"=="1000"`、`null==false`），PHP 8 改了字符串与数字比较。安全比较用 `hash_equals`。

**Q4 数组** — **有序哈希表**，既是 list 又是 map，遍历顺序可靠；扩容 2 倍、冲突用链表/桶。

**Q5 引用与 foreach** — 值传递 + **COW**；对象传句柄（不是引用）；`foreach (&$v)` 后必须 `unset($v)`，否则下一次循环污染。

**Q6 闭包** — `use` 按值捕获，`use (&$x)` 按引用；闭包是对象，`bindTo` 可换作用域。

**Q7 魔术方法** — `__construct/__get/__set/__call/__toString/__invoke/__destruct`；`__get` 滥用会让代码难查，性能也差。

**Q8 接口/抽象类/trait** — 接口定契约、抽象类带实现、trait 横切复用方法（不能实例化，冲突用 `insteadof`）。

**Q9 Composer** — PSR-4 命名空间映射 → `composer dump-autoload` 生成 classmap；`composer.lock` 必须提交。

**Q10 Laravel 生命周期** — `index → Kernel → bootstrap（配置/门面/服务提供者）→ Pipeline（洋葱中间件）→ Router → Controller → Response → terminate`。

**Q11 中间件** — `array_reduce` 反序包裹成闭包链，`$next($request)` 就是下一层；前置/后置逻辑分居两侧。

**Q12 N+1** — `with()` 预加载、`chunkById` 分批、`cursor()` 游标；用 `DB::listen` 或 Telescope 抓查询数。

**Q13 事务嵌套** — MySQL 无真嵌套，Laravel 用 **Savepoint** 模拟；事务内不做 RPC 与长耗时操作。

**Q14 SQL 注入防御** — 值用**参数绑定**、标识符（表/列/排序）只能**白名单**；`EMULATE_PREPARES=false` 才是真预处理；`IN` 动态占位符、`LIKE` 转义 `%_`。

**Q15 XSS/CSRF/上传/反序列化** — 输出转义 + CSP；CSRF Token + SameSite；上传校验 MIME+后缀+重命名+存对象存储不落 web 目录；`unserialize` 禁用，改 JSON。

**Q16 Session** — 多机共享用 Redis；同用户并发请求会**覆盖 session**，需要 `session_write_close` 或按需加锁。

**Q17 FPM 调优** — `max_children = 可用内存 ÷ 单进程内存`；`pm=static` 稳、`dynamic` 省；`max_requests` 防内存碎片。

**Q18 性能排查** — 先看慢日志与 APM → 定位 SQL/外部调用 → opcache/JIT → 再看代码热点（xhprof）。**先量化再优化**。

**Q19 Swoole** — 常驻内存 + 协程，QPS 高但**状态要自己管**（全局变量会跨请求残留）、调试与生态成本高。

**Q20 PHP 8** — JIT、命名参数、构造器属性提升、match、联合类型、`readonly`、枚举、`str_contains` 等新函数。

# 五、MySQL（20 题）

**Q1 执行流程** — 连接器 → 解析器 → 优化器 → 执行器 → 引擎。统计信息不准会选错索引；`SQL_NO_CACHE` 时代已过去，看 `optimizer trace`。

**Q2 InnoDB vs MyISAM** — 事务/行锁/聚簇/MVCC/崩溃恢复 vs 表锁/无事务。**默认永远 InnoDB**。

**Q3 B+ 树** — 非叶子只存键、叶子成链表；**三层约 2000 万行**，1~3 次 IO；范围查询顺链表扫。

**Q4 聚簇与覆盖** — 主键存整行、二级存主键；**覆盖索引免回表**（`Using index`）；主键要短、要自增。

**Q5 最左前缀与 ICP** — **等值在前、范围在后**；范围列之后无法继续定位；**索引下推**把过滤下推到引擎层减少回表。

**Q6 索引失效** — 函数、隐式转换、前导 `%`、`OR`（一侧无索引）、违背最左、区分度低、`!=`。

**Q7 explain** — 看 `type`（ref/range 可接受，ALL 要改）、`key`、`rows`、`Extra`（`filesort`/`temporary` 是信号）。

**Q8 慢查询动作** — 开慢日志 → `explain` → 加/改联合索引或改写 SQL → 对比扫描行数与 P99。**用数据说话**。

**Q9 深分页** — 延迟关联（先取 id 再 join）或游标 `where id > ?`；`limit 100000,20` 会扫掉前 10 万行。

**Q10 ACID** — A 靠 undo、C 靠约束与触发器+应用、I 靠锁与 MVCC、D 靠 redo + `innodb_flush_log_at_trx_commit`。

**Q11 MVCC** — 隐藏列（trx_id/roll_ptr）+ undo 版本链 + ReadView。**RC 每条语句生成、RR 首次生成并复用**。

**Q12 三种日志** — redo 物理（持久）、undo 逻辑（回滚/MVCC）、binlog 归档（复制/恢复）；**两阶段提交**对齐 redo 与 binlog。

**Q13 锁** — 表锁/行锁/意向锁、记录锁/间隙锁/Next-Key、共享/排他；**行锁依赖索引**，没走索引会锁全表；MDL 让 DDL 与 DML 互斥。

**Q14 死锁** — 查 `SHOW ENGINE INNODB STATUS`；预防：固定加锁顺序、事务短、走索引、失败重试。

**Q15 主从** — dump → relay → 回放三线程；延迟真因是**大事务 + 单线程回放 + 资源竞争**；并行复制、GTID 等待、关键读走主。

**Q16 分库分表** — 顺序：**优化 → 归档 → 读写分离 → 垂直拆 → 水平分片**；分片键决定一切，跨片 join/事务是代价。

**Q17 大表 DDL** — Online DDL（8.0 支持多数在线）或 **gh-ost / pt-osc**；低峰 + 限速 + 观察主从延迟。

**Q18 表设计** — 主键短且自增、字段 NOT NULL 带默认、金额用整数分、状态用 tinyint、必备 created_at/updated_at、避免大字段与过多索引。

**Q19 连接池** — 连接是昂贵的有状态资源；池上限按 `DB max_connections ÷ 实例数` 算；**事务必须同一连接**，忘记 release 会耗尽池。

**Q20 MySQL 优化案例** — 现象（P99 涨）→ 证据（慢日志 + explain 的 rows/type）→ 动作（联合索引/改写/归档）→ 结果（扫描行数 N→M、P99 降 X%）。**数字必须是真的**。

# 六、Python（18 题）

**Q1 可变/不可变与默认参数** — **默认参数只求值一次**，可变默认值会跨调用累积 → 用 `None` 占位再初始化。

**Q2 深浅拷贝** — 赋值不加成本（同一对象）、`copy` 一层、`deepcopy` 递归（注意循环引用与性能）。

**Q7 dict** — 哈希表 + 开放寻址，**3.7 起保证插入有序**；扩容 2/3 负载因子；key 必须可哈希。

**Q8 异常** — 只捕获具体异常、`raise ... from e` 保留链、`finally` 做清理、别用异常做控制流。

**Q9 线程/进程/协程** — CPU 密集进程、IO 密集线程、**高并发 IO 用 asyncio**；协程里禁止阻塞调用。

**Q10 asyncio** — 事件循环 + `await` 让出；`gather` 并发、`Semaphore` 限流、`wait_for` 超时；阻塞库用 `run_in_executor`。

**Q11 GC** — 引用计数为主 + **分代回收处理循环引用**；`gc.freeze()` 可在 fork 前减少 COW 开销。

**Q12 Django** — 中间件正逆序执行；**QuerySet 惰性**；`select_related`（JOIN，外键）、`prefetch_related`（两次查询，多对多）。

**Q13 部署** — Nginx 静态 + uWSGI/gunicorn 动态；进程数 `2×核数+1`；**WSGI 是协议契约**，ASGI 支持异步。

**Q14 TaskFlow** — `Flow + Task(execute/revert) + 状态持久化 + 逆序补偿`；三关键词：**幂等、对账、互斥**。

**Q15 包管理** — venv/conda 隔离、`requirements.txt` 或 poetry 锁版本；**生产锁死版本**，别用最新。

**Q16 性能优化** — `cProfile` 找热点 → 换数据结构/批量 IO/向量化（numpy）→ 必要时下沉到 C/Go。

**Q17 与 PHP/Go 差异** — 动态+简洁 vs 类型严格/并发原生；Python 适合数据处理与编排，Go 适合高并发接入。

**Q18 RDS-Core 实践** — 用 Python 写任务引擎与运维脚本：**编排、补偿、对账**，把"人工点按"变成"可恢复的流程"。

# 七、Redis（26 题）

> 与第八节「滴滴专项」下的 Redis 8 题互补：那 8 题是面经真题，这里是通用体系题。

**Q1 为什么快** — 纯内存 + **单线程无锁** + epoll 多路复用 + 高效结构；瓶颈在**网络与内存**不在 CPU。代价：长命令阻塞全场。

**Q2 6.0 多线程** — 只并行**网络读写与协议解析**，命令执行仍单线程；`io-threads` 建议 4，超 8 收益递减。

**Q3 类型与编码** — string：`int / embstr(≤44) / raw`；hash、zset：`listpack → hashtable / skiplist+dict`（128 个或 64 字节）；set：`intset → hashtable`。**转换单向不可逆**。

**Q4 SDS** — `len + alloc + buf`：O(1) 长度、二进制安全、防溢出、预分配（<1MB 翻倍，≥1MB 加 1MB）。

**Q5 事务** — `MULTI` 入队、`EXEC` 执行；**运行期错误不回滚**（只有语法错误整体拒绝）；`WATCH` 是乐观锁，条件逻辑改用 Lua。

**Q6 Lua** — 整体原子、不被插入；Cluster 必须**同槽**（hash tag `{}`）；超 `lua-time-limit`（5s）返回 BUSY；生产用 **EVALSHA**。

**Q7 pipeline** — 省 **RTT**，但**不保证原子**；`MSET/MGET` 是单命令才原子；一批 500~1000 条。

**Q8 KEYS / SCAN** — `KEYS` O(N) 阻塞必须禁用；`SCAN` 游标分批，**可能重复、不保证顺序**，`COUNT` 只是提示。

**Q9 RDB** — fork 子进程 + **COW**；恢复快，丢快照之后的数据；fork 卡在**页表**，单实例 ≤10GB、关 THP。

**Q10 AOF 策略** — `always` 不丢但慢 / **`everysec` 丢 1 秒（默认）** / `no` 靠系统；7.0 **multi-part**（base + incr + manifest）。

**Q11 AOF 重写** — **读内存重新生成**，不是抄旧文件；期间双写**重写缓冲区**，最后原子替换。

**Q12 混合持久化** — 前段 RDB、后段 AOF：恢复快又少丢；老版本与部分工具不兼容。

**Q13 主从复制** — `PSYNC + replid/offset`；全量 = RDB + replication buffer；增量靠 **repl_backlog**（默认 1MB，易被冲掉）；复制**异步所以会丢数据**。

**Q14 哨兵** — `SDOWN → ODOWN`（quorum）→ 选 leader（**多数票**）→ 选新主（优先级 / offset / runid）；脑裂靠 **min-replicas-to-write**。

**Q15 Cluster** — **16384 槽**（CRC16）；**MOVED 改槽表、ASK 不改**；可用 = 槽全覆盖 + **主节点过半可达**；多 key 用 hash tag 同槽。

**Q16 缓存一致性** — **先更新 DB、再删缓存**（不是"更新缓存"）；缝隙用**延迟双删 / binlog 订阅 / 过期兜底**收敛。

**Q17 布隆过滤器** — k 个哈希 + bitmap：**没有一定没有，有不一定有**；**不能删**（用计数布隆/布谷鸟）；`m = -n·lnp/(ln2)²`。

**Q18 淘汰策略** — 8 种 = `allkeys/volatile` × `lru/lfu/random/ttl` + `noeviction`；**近似 LRU 采样 5 个**；热点稳定用 LFU 防批量冲掉。

**Q19 内存碎片** — ratio **> 1.5** 关注、**< 1** 说明 swap；`activedefrag yes` 或重启；TTL 加随机抖动。

**Q20 慢查询** — `slowlog` 看**命令执行时间**（不含网络）、`latency monitor` 看**事件**（fork/fsync/集中过期）、`--bigkeys` 看结构。

**Q21 连接与"能不能当 MQ"** — 连接池 + 命令超时 + 幂等重试；List **没有 ACK** 不能当队列，用 **Stream**（消费组 + PEL）。

**Q22 排行榜** — ZSet：`ZINCRBY / ZREVRANGE / ZREVRANK`；**同分按字典序**，要"先到先得"就把时间编进 score 低位；周期榜分 key。

**Q23 秒杀** — 预热 → **Lua 原子扣减（判断 + DECR + SADD）** → MQ 异步落库 → 唯一索引幂等 → DB `stock>0` 兜底 → 对账回补。

**Q24 限流** — 固定窗口有**临界双倍**；滑动窗口用 ZSet；**令牌桶最常用**（允许突发）；全部靠 Lua 保证原子。

**Q25 会话与验证码** — String + TTL **滑动续期**；JWT 无状态但**难主动失效**，踢人用版本号；验证码一次性 + `NX` 防覆盖。

**Q26 Stream** — `XADD / XREADGROUP / XACK / PEL / XAUTOCLAIM / XTRIM` 六件套；有消费组与重投，但无事务消息，必须裁剪。

# 八、滴滴专项（44 题）

**节奏**：三轮技术面，**每轮都写代码**。一面八股 + 一道算法，二面项目深挖 + 场景设计，三面架构与判断力。技术栈 Go + Kafka + MySQL + Redis Cluster + HBase + K8s。

## 必写算法 12 道

- **交替打印 1~100** — 两个 channel 传令牌、**只发一个初始令牌**；N 个则环形传；也可 Mutex+Cond。
- **LRU** — `map[key]*list.Element` + `MoveToFront` + 超容删尾；追问：近似 LRU（采样 5 个）、并发安全（分片/单 goroutine 串行化）。
- **层序遍历** — queue + 每层先记 size。
- **最大子数组和（含路径）** — `dp[i]=max(dp[i-1]+a[i], a[i])`，记 `start` 回溯。
- **只出现一次的元素** — 全异或；两个数按最低位 1 分组再异或。
- **N 个有序数组交集** — k 路归并、**对齐到当前最大值**；并集取最小值去重。
- **斜着遍历矩阵** — 按 `i+j` 分组，偶数层反向。
- **无锁环形队列** — 槽位 `seq` + CAS head/tail + **缓存行填充**；有锁版先写。
- **拿球博弈（1~7，拿最后者赢）** — **必败点 n%8==0**，先手取 `n%8` 个。
- **最小比较次数求最大最小** — 两两配对，**3n/2-2** 次。
- **K 个一组反转链表** — 哑结点 + 组内反转 + 正确接线。
- **最长无重复子串** — 滑动窗口 + lastIndex 跳转。

## Go 补充 12 题

- **G1 map 空值/new/make** — 零值不区分有无 → 用 `v, ok`；nil map 读安全写 panic；new 给指针、make 给结构。
- **G2 GC 哪个阶段不扫描** — **sweep 按 markBits 回收，不扫对象图**；Go **无分代**（别说年轻代）。
- **G3 GMP 演进** — 1.1 全局队列锁 → 1.2 P+本地队列+stealing → 1.5 GOMAXPROCS → 1.14 SIGURG 抢占；**runnext + 每 61 次必查全局队列**。
- **G4 无锁并发 map** — 分片锁通用 / `sync.Map` 读多写少 / COW 极低频写。
- **G5 sync.Once** — atomic 快路径 + mutex 慢路径 + **双检** + defer 置位；f panic 后不再重试。
- **G6 交替打印** — 见算法清单第 1 条（一面真题，10 分钟）。
- **G7 LRU** — 见算法清单第 2 条（二面真题）。
- **G8 环形队列** — 见算法清单第 8 条（三面真题）。
- **G9 有序数组交并集** — 见算法清单第 6 条。
- **G10 CPU/IO 打满** — CPU：`top → top -Hp → 16 进制 → pprof 火焰图看最宽叶子`；IO：`iostat -x` 看 util/await → 分磁盘/网络/下游。
- **G11 channel vs 锁** — **传数据用 channel，护状态用锁**；判断标准："这东西会换主人吗"。

## Redis 8 题（滴滴向，通用题见第七节）

- **R1 zset** — 小 listpack、大 **skiplist + dict**；跳表赢在范围查询与实现简单。
- **R2 渐进式 rehash** — `ht[0]/ht[1] + rehashidx + 每次搬一个桶 + 查两表写新表`；有子进程时阈值升到 5。

- **R6 分布式锁** — `SET NX PX` + 唯一 value + **Lua 比对删除** + 看门狗 + 主从丢锁靠 **fencing token**。
- **R7 三兄弟** — 穿透（空值+布隆）/ 击穿（singleflight）/ 雪崩（抖动+多级+降级）。

## 出行业务场景 7 条主线（二面主战场）

- **S1 订单状态机** — `CREATED→MATCHED→PICKUP→IN_TRIP→PENDING_PAY→COMPLETED` + 取消/超时分支；**迁移白名单 + CAS + 事件表**。

# 九、项目一句话主线（13 条）

- **RDS 任务引擎** — "TaskFlow 把运维操作拆成带 `revert()` 的 Task，失败**逆序补偿**，补偿**幂等**（任务 ID+步骤号去重），失败进重试队列 + **对账**兜底。"
- **回滚一致性** — "没有全局事务就用 **Saga 补偿**：只补偿已产生副作用的部分，状态机显式区分执行中/已回滚/回滚失败。"
- **状态不一致** — "**append-only 操作日志 + 定时对账**（扫超时任务，反查真实资源状态修正）。"
- **LB 清理异常** — "**清理顺序 + 幂等重试 + reconcile**：解注册做成异步可重试，升级后比对 LB 实际后端与期望后端。"
- **GDP2 分层** — "router → service → dao → model，启动注入配置与组件，**错误逐层包装上抛**。"
- **校验规则组织** — "**策略模式 + 注册表**，统一 `Check()`，**收集全部问题而非遇错即返**，规则可配开关。"
- **热重启** — "SIGUSR2 → fork 继承 listener fd → 子进程 accept → 父进程 Shutdown 排空 → 退出。"
- **SQL 注入整改** — "值用**参数绑定**，标识符只能**白名单**；`IN` 动态占位符、`LIKE` 转义；再加**最小权限 + SAST 卡口**。"
- **硬编码治理** — "敏感参数外置配置中心、密钥走 **KMS**、按环境分离、**CI 加 gitleaks 防回归**。"
- **MySQL 优化** — "慢日志 → `explain` 看 type/rows/filesort → 加联合索引或改写 → 扫描行数 N→M，P99 降 X%。"
- **Redis 抢购** — "库存预热 + **Lua 原子扣减** + MQ 异步落库 + **DB 唯一约束兜底**。"
- **分布式锁** — "`SET NX PX` + 唯一 value + Lua 比对删除；生产更信**单 Redis + 业务幂等**，别迷信 RedLock。"
- **Kafka 不丢** — "生产 `acks=all` + 幂等；broker 三副本 + `min.insync=2`；消费**手动提交 + 幂等**。"

# 十二、考前 10 分钟速记卡

**Go 关键词链**
- defer：`LIFO → return 三步 → 命名返回值`
- slice：`三元组 → 256 翻倍 → 共享底层数组`
- map：`fatal 不可 recover → RWMutex/sync.Map/分片锁`
- 并发：`GMP（G 协程 / M 线程 / P 调度资源）→ 本地队列 256 → work stealing → syscall handoff → SIGURG 抢占`
- channel：`nil 阻塞 → closed 发送 panic → 谁发送谁关闭`
- context：`树 → Done 关闭即广播 → 首参 → defer cancel`
- GC：`三色标记 → 混合写屏障 → STW 亚毫秒 → GOGC/GOMEMLIMIT`
- 逃逸：`返回指针/闭包/装箱 → -gcflags=-m`
- 锁：`1ms 饥饿模式 → RWMutex 写优先 → 不可重入`
- 工程：`-race → pprof 火焰图看最宽叶子`

**如果被问"讲讲你对 Go 的理解"（30 秒，直接背）**
"Go 的设计取向是**用简单的语言特性换工程可维护性**。并发模型是 **CSP**：goroutine 表达并发、channel 传递数据、context 管生命周期，避免共享内存加锁；运行时靠 **GMP 调度 + netpoller** 支撑高并发 IO，靠**并发三色标记 GC** 控制停顿。代价是错误处理显式啰嗦、泛型能力有限，换来编译快、单二进制部署、团队上手成本低。"

**Node 关键词链**
- 循环：`六阶段 → 阶段间清 nextTick 再清微任务 → poll 是核心`
- 线程：`JS 单线程 → 线程池 4（fs/dns/zlib/crypto）→ 网络走 epoll`
- 模块：`CJS 值拷贝有 cache → ESM 静态活绑定`
- 流：`highWaterMark → write false 等 drain → 用 pipeline`
- 框架：`Express 函数数组 + 4 参错误中间件 → Koa 递归 compose`
- 多进程：`cluster handle + round-robin → 状态外置 Redis`
- 稳定性：`uncaughtException 就 exit → 泄漏看快照 Retained Size`
- 性能：`clinic flame → 大 JSON / ReDoS / GC`

**AI 关键词链**
- 原理：`QKᵀ/√d_k → O(n²) → KV Cache 显存大头`
- 三阶段：`预训练知识 → SFT 格式 → RLHF 偏好`
- RAG：`切 300~800 带重叠 → 向量+BM25 → rerank 最划算 → 只依据材料给引用`
- FC：`模型只输出 JSON → 应用执行 → 结果回灌 → 循环`
- Agent：`ReAct 三步 → 步数/超时/白名单/人工确认`
- MCP：`JSON-RPC → Tools/Resources/Prompts → M×N 变 M+N`
- 评估：`golden set → Recall@k + Faithfulness → LLM-as-judge`
- 安全：`权限隔离最硬 → 输入分隔 → 白名单 → 审计`

**PHP / MySQL / Python 三行**
- PHP：`生命周期五阶段 → opcache/JIT → 参数绑定+标识符白名单 → FPM max_children 按内存算`
- MySQL：`B+ 三层两千万 → 覆盖索引免回表 → MVCC(RC 每条/RR 首次) → 两阶段提交`
- Python：`默认参数只求值一次 → GIL 限 CPU 不限 IO → TaskFlow 逆序补偿 = Saga`

**Redis 关键词链**
- 模型：`纯内存 + 单线程执行 + epoll`；6.0 IO 多线程只搬数据不碰账本
- 编码：`string int/embstr(44)/raw → hash、zset listpack(128 个/64 字节) → skiplist+dict`，**单向不可逆**
- 持久化：`RDB=fork+COW → AOF everysec 丢 1 秒 → 7.0 multi-part(base+incr+manifest) → 混合前 RDB 后 AOF`
- 高可用：`PSYNC replid/offset → backlog 1MB → 哨兵 SDOWN/ODOWN/多数票 → Cluster 16384 槽、MOVED 改表 ASK 不改`
- 缓存：`先写库后删缓存 → 延迟双删/binlog → 穿透布隆、击穿 singleflight、雪崩抖动`
- 内存：`8 种策略 → 近似 LRU 采样 5 → 碎片 >1.5 开 activedefrag`
- 原子：`MULTI 不回滚 → Lua 整体原子 + Cluster 同槽 → 生产用 EVALSHA`
- 场景：`排行榜 ZSet 编时间 → 秒杀 Lua 扣减+MQ+唯一索引 → 限流令牌桶 → 队列用 Stream`

**滴滴关键词链**
- 节奏：`三轮都写代码 → 一面八股+算法 → 二面场景+项目 → 三面架构`
- 算法：`令牌 channel → LRU map+list → 无锁环 seq+CAS → 博弈 n%8`
- 场景：`状态机 CAS → 一单一人三层 → GEO 9 格 → 25w QPS 只留最新 → 计费幂等对账`
- 定位：`位置只留最新、轨迹另存` / `DB 不能弹，靠缓存和队列`
